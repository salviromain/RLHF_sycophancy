# RLHF Sycophancy Mitigation Pipeline

This repository contains the full workflow we used for a CS 594 project on reducing sycophantic behavior in large language models using supervised fine-tuning (SFT), automated benchmarks, and human preference studies. It covers data preparation, model training, automated evaluation, and a Google Apps Script based interface for structured human feedback.

---

## Repository Layout

- `sycophancy_dataset.jsonl`  Source prompts with correct/incorrect answers (Redwood-style sycophancy dataset)
- `questions_syc.jsonl`, `questions_cc.jsonl`  Benchmark subsets for automatic inference (sycophancy focus vs. CyberChallenge logical puzzles)
- `Llama3_answers.csv`  Collected generator, critique, and revision responses with judge decisions (training-ready table)
- `to_jsonl.py`  Utility to turn judge CSV files into Azure-compatible JSONL chat traces
- `RLHF_SFT2.ipynb`  End-to-end SFT and inference workflow for Llama 3 8B with LoRA adapters
- `inference_results_questions_*.csv`  Saved generations from base vs. fine-tuned models for each benchmark split
- `form_generator.py`  Script that produces a Google Apps Script file (`form_creator_script.js`) for preference collection
- `FormPage.html` / `form_creator_script.js`  Web UI and Apps Script automation for the human evaluation form and aggregation
- `stats_getter.py`  Helper to summarize annotator CSVs (agreement rates, decision breakdowns)
- `Analysis_adversarial.ipynb`, `Part1RL_triAgent.ipynb`  Exploratory notebooks and earlier experimentation
- `form_creator_script.js`  Example Apps Script generated by `form_generator.py`
- `FormPage.html`  Front-end served by the Apps Script web app
- Misc CSV/JSON artefacts capture intermediate data states for reproducibility

---

## Prerequisites

- Python 3.12+ (tested on Google Colab)
- CUDA-capable GPU with at least 16 GB VRAM for full 8B fine-tuning, or adapt the notebook to use 4-bit quantization
- `pip` for installing Python dependencies
- (Optional) Google Workspace access to deploy the human evaluation form and Apps Script

The main notebook installs its own dependencies inside the runtime, but the standalone scripts expect: `pandas`, `datasets`, `transformers`, `accelerate`, `trl`, `peft`, `unsloth`, and `tqdm`.

---

## Pipeline Overview

1. **Dataset preparation**  Clean judge outputs, produce JSONL traces for SFT, and sanity-check label quality.
2. **Supervised fine-tuning (SFT)**  Train LoRA adapters on Llama 3 8B using the curated dataset.
3. **Automatic benchmarking**  Compare base vs. fine-tuned generations on sycophancy and counterfactual question sets.
4. **Human preference evaluation**  Collect blinded side-by-side ratings via a Google Apps Script web form.
5. **Reporting**  Aggregate automatic metrics and human judgments into tables and plots.

Each stage below explains the concrete commands and files involved.

---

## Stage 1. Dataset Preparation

### 1.1 Inspect judge output quality

Use `stats_getter.py` on any CSV that contains columns `prompt, yG, c, yR, judge1, judge2, judge3, final_decision` to understand agreement and coverage.

```pwsh
python stats_getter.py Llama3_answers.csv
```

The script prints counts for empty revisions (`yR`), judge agreement rates, and how often the final decision leans toward the generator (`yG`) or revision (`yR`). Adjust filtering criteria accordingly.

### 1.2 Convert tabular data into JSONL traces

`to_jsonl.py` turns the judge CSV into OpenAI-compatible chat fine-tuning data. By default it reads `judge_results_checkpoint_updated.csv` and writes `sft.jsonl`; override the paths if needed.

```pwsh
python to_jsonl.py
```

Each line in the output looks like:

```json
{"messages": [
  {"role": "user", "content": "PROMPT"},
  {"role": "assistant", "content": "INITIAL RESPONSE"},
  {"role": "assistant", "content": "CRITIQUE: ..."},
  {"role": "assistant", "content": "REVISED: ..."}
]}
```

This format feeds the SFT notebook directly or can be submitted to Azure OpenAI fine-tuning APIs.

## Stage 2. Fine-Tuning With `RLHF_SFT2.ipynb`

The notebook bundles data loading, LoRA setup, training, and inference. Recommended flow:

1. **Open the notebook** in VS Code, Jupyter Lab, or Colab.
2. **Run the setup cells** to install dependencies (`torch`, `unsloth`, `trl`, etc.). GPU support is required.
3. **Load data** via `load_and_prepare_data("Llama3_answers.csv", test_ratio=0.1)`.
	- Rows where the judges prefer `yR` are retained.
	- Group-aware splitting keeps correlated prompt variants together.
4. **Configure training** parameters near the top (LoRA rank, learning rate, epochs, 4-bit loading).
5. **Launch training** by executing the main block under `if __name__ == "__main__":`.
	- LoRA adapters are stored in `./llama3-finetuned/`.
6. **Optional: Save/Load** the adapters using `FastLanguageModel.from_pretrained` and `PeftModel.from_pretrained` as shown.

The notebook also defines two prompt templates:
- `format_training_sample` adds an `<internal_thought>` block to teach the refine-and-critique routine.
- `create_inference_prompt` is a clean chat-style prompt for deployment.

Changing the dataset path or hyperparameters only requires editing the constants at the top of the notebook.

## Stage 3. Automatic Benchmarking

The second half of `RLHF_SFT2.ipynb` runs inference on JSONL benchmarks:

```python
test_files = ["questions_syc.jsonl", "questions_cc.jsonl"]
run_inference_tests(test_file, model, tokenizer)
```

`run_inference_tests` will:

- Load each JSONL sample (the prompt is in `data["base"]["question"]`).
- Generate answers with the base model and the fine-tuned adapters.
- Save paired generations to `inference_results_<benchmark>.csv` with columns `prompt`, `correct_answer`, `base_response`, `finetuned_response`.

You can execute the inference block immediately after training (models kept in memory) or independently by reloading adapters from disk.

Use these CSVs to compute automatic accuracy metrics or to sample items for human evaluation.

## Stage 4. Human Preference Evaluation

We capture structured human feedback via a Google Apps Script web form.

### 4.1 Prepare evaluation CSV

Create `evaluation_data.csv` with columns `prompt`, `original`, `improved`.
- `original` typically stores the base model answer.
- `improved` stores the fine-tuned answer.
- The script will randomize ordering per-question to ensure blinding.

Sample rows can be copied from `inference_results_questions_*.csv`.

### 4.2 Generate Apps Script code

```pwsh
python form_generator.py
```

This produces `form_creator_script.js`, which contains:
- A randomized subset of questions (set by `MAX_TOTAL_QUESTIONS` and `REQUIRED_QUESTIONS_COUNT`).
- Helper functions to build the form structure and aggregate results into a Google Sheet tab `Aggregated Results`.

### 4.3 Deploy in Google Apps Script

1. Create a Google Sheet and open **Extensions > Apps Script**.
2. Paste the contents of `form_creator_script.js` into `Code.gs`.
3. Add a new HTML file named `FormPage` and paste `FormPage.html` from the repo.
4. Run `createLLMEvaluationForm` once to seed the form and connect it to the sheet (authorize the script when prompted).
5. Publish the web app via **Deploy > Test deployments** to share the survey page generated from `FormPage.html`.
6. After data collection, run `aggregateResults()` from the Apps Script IDE. Results appear in the `Aggregated Results` sheet with per-question win rates and preference scores.

`FormPage.html` provides a polished single-page survey experience with compulsory initial comparisons and optional extras. Feel free to customize text copies and styling before deployment.

## Stage 5. Reporting and Analysis

- Use `stats_getter.py` on exported form responses (after downloading to CSV) to quantify agreement between judges or to verify how often `final_decision` aligns with each model.
- Combine `inference_results_questions_*.csv` with human preference tallies from the Google Sheet to plot win rates and accuracy deltas.
- `Analysis_adversarial.ipynb` and `Part1RL_triAgent.ipynb` contain additional exploratory analyses; adapt them to visualize new results.

## Reproducing End-to-End

1. **Inspect and clean data**  (`stats_getter.py`, manual review of `Llama3_answers.csv`).
2. **Produce SFT training set**  (`python to_jsonl.py`).
3. **Fine-tune Llama 3**  (run `RLHF_SFT2.ipynb`; verify adapters save to `llama3-finetuned/`).
4. **Benchmark automatically**  (execute the inference block; produce `inference_results_questions_*.csv`).
5. **Collect human preferences**  (`form_generator.py` -> Apps Script deployment -> aggregate results).
6. **Summarize findings**  (rerun `stats_getter.py`, update notebooks, export tables/plots).

Keep the generated artefacts under version control or store them with run metadata (model checkpoint hash, commit SHA, dataset version) to maintain reproducibility.

## Troubleshooting

- **Out-of-memory while training**  Lower `BATCH_SIZE`, enable `LOAD_IN_4BIT = True`, or shorten `MAX_SEQ_LENGTH` in the notebook.
- **Apps Script cannot find sheets**  Ensure the script is container-bound to the Google Sheet (open Apps Script from inside the sheet) and that tabs `Questions`, `Responses`, and `Aggregated Results` exist or are auto-created.
- **Empty `yR` values**  `stats_getter.py` highlights rows lacking revisions; consider filtering them before training so the model learns from high-quality critiques.
- **Inference script crashes on CPU**  `FastLanguageModel` expects CUDA; run the notebook on a GPU instance or adjust to CPU-friendly settings (e.g., smaller model, quantized weights).

For further questions, open an issue or reach out to the course team.
